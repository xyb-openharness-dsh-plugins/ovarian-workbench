# 少核对、先获得帮助：一期任务与数据合同 v0.1

依据：用户提供E03/E04处境，并要求继续完成设计。此前Q4没有单独明确答复；本轮由设计者采用“先提供可回源的未核对草稿，仅询问少数影响理解的疑点、允许跳过”作为可修改的设计基线DB01。它不是用户已确认的准确率、自动诊断或免核对承诺。

## 1. 两个开始方式，共享后续资料

**刚确诊，不知道怎么办（F01/S1）：** 无资料也能开始→简短承接感受→可跳过地选择眼前需要→给可读懂的已知/未知与一两件可做的沟通/求助准备→自愿保存或暂停。没有联系人、家属或已配置资源不阻塞；不知道如何就医时提供维护过的官方信息查找说明，未核实渠道明确说明。不给统一的“必须做完”检查或治疗清单。

**资料很多，帮我理清楚（R05/S2）：** 批量交材料→系统分类/去重/时间对齐→短整理草稿→原文与疑点按需展开→保留问题/接受少数记录→复诊材料预览。无需先排时间、命名文件、说清全部病史或想好问题。不能承诺本期读取DICOM影像作诊断；一期按影像文字报告整理。

通用静态导航在未绑定资料目录/无原生会话时也可只读；保存个人事项/资料时才引导选择本机目录，调用云模型时按宿主权限和发送范围处理。

两个入口都是患者任务，既有病情/指标/一图秀/临床等模块仍保留完整范围。入口不按分期或情绪评分自动选择，也不因新确诊就屏蔽完整模块。

## 2. 系统先完成什么，用户只需做什么

| 系统承担 | 用户可选动作 | 不能偷换的含义 |
| --- | --- | --- |
| 保留原件，识别类型、重复、日期，提取可定位文字 | 一次选择文件、查看处理状态 | 文件已处理不等于所有材料齐全 |
| 组织报告/治疗事件、指标、影像比较出处 | 只看短草稿，按需打开来源 | 自动排序不代表临床先后/因果已确定 |
| 识别任务依赖的日期/单位/来源冲突等疑点 | 接受、更正、拒绝、暂跳过；允许整批稍后 | 看过摘要、关闭疑点或保存结果不等于接受全部字段 |
| 用适用且可核对的来源解释已有信息，提出候选问题 | 保留/删改问题，选择是否请获授权的人帮忙 | 系统提出的问题不是患者已经表达的意愿 |
| 增量使用已接受记录和本批候选，标出变化 | 只处理新增或被更正的部分 | 没有新变化不要求反复确认旧资料 |

## 3. 草稿与已接受数据的合同

使用已有处理状态，不另建两套事实库。`candidate/needs_review`可被**草稿读模型**引用，`accepted`供**已接受记录读模型**使用；`rejected/superseded`不作为当前结果依据。草稿由记录ID/版本和状态组成，不自动复制到正式观察值/治疗记录。

| 位置 | 默认内容 | 用户额外选择与标识 |
| --- | --- | --- |
| 病情档案/指标列表/临床档案 | 已接受记录；另列待核对入口及数量 | 查看原文/候选，不把候选混为当前确切病情 |
| 短整理草稿 | 本批有出处的候选摘录、已接受资料及其区别 | 每个实质性说法可展开引用与核对状态；页首写“整理草稿，尚有内容未核对”，不能只藏在页脚 |
| 解释/讨论选项 | 已接受背景和明确标为暂定的材料摘录 | 关键依赖未确定时，只解释报告原文/一般知识并列出问题，不据此筛选个体药物、计算趋势结论或判断进展 |
| 一图秀 | 已接受指标及实际治疗，保留既有刻度/可比性规则 | “预览本批待核对材料”需主动打开；候选仅作分开的点/事件和待核区，不与已接受值连线；日期/单位不明不强行定位 |
| 复诊导出 | 默认用已接受记录；缺项和讨论问题可包含 | 用户可明确包含草稿摘录；预览和所有格式保留逐条核对状态、来源、冲突/缺项，不能一键导出时自动抹标签 |

从候选信息派生的解释、问题和后续回复，继承所依赖记录的核对状态/版本。问题若预设候选事实（例如候选指标“升高”），默认导出也视为包含该候选，需明确选入并保留来源/状态；或改写成不预设事实的核实问题，例如“请帮我核实这次报告结果及其与以往记录是否可比”。不能借问题形式绕过草稿导出选择。

影像变化只引用报告已写的结论与比较对象；没有对照报告/实际治疗日期时显示未知，不把用户“大致了解进展”的自述替代医生或影像结论。医学外部来源仍需版本/地区/适用限制。

## 4. 重点疑点怎么选，如何允许不处理

疑点来自可检测的数据问题：无出处、读不清、多个值冲突、单位不明、采样/报告日混淆、影像比较对象不明、计划/实际给药未区分。只有当这些问题影响当前被请求的摘要/解释时，才提到前面；其余留在可展开队列。

每轮默认呈现至多三个相互独立的疑点（设计起点，待负担走查调整）。明确“为什么需要这条、跳过后哪里仍不确定”，可一键“现在先不核对”，后续仍能阅读有来源草稿与准备问题。不得将OCR自评分包装成经过验证的医学可信度，也不把长红色错误列表作为主界面。

如果用户明确接受一组字段，先展示该组原文与差异，记录实际接受ID/版本/操作者；不把整份报告的任何一次点击当全部接受。源文件重解析产生新候选，不撤销原接受记录；差异需新一轮核对，相关草稿/摘要标旧版本。

## 5. 新确诊支持的具体语言和离线状态

首屏示例：“一下子面对这么多消息，可能很难消化。我们可以慢慢来，先把眼前的一件事理清楚。”这是文案提案，不承诺康复、治疗效果或即时真人陪伴。允许“暂时不想说”“先看看”“以后再继续”；不要求先回答长问卷或做心理量表。

保存的下一步区分：沟通准备、查找信息、本人自定事项、已有医嘱安排。系统建议不能自动写成医嘱或实际给药；外部联络/发送仍需明确动作。本期不新增远程家属账号/专业转介平台。无模型/网络时提供本地维护的基础说明、个人问题草稿和已配置或官方渠道查找说明，显示其更新/核验状态。

## 6. 闭环结果及可观察目标

J1用户能在不建完整档案时读懂一小步，可暂停且不丢草稿；J2用户仅交材料就能看到可回源的短整理、知道哪些仍不确定、保留问诊问题，之后不重填进入复诊准备。短摘要默认展示重点，详细字段和引用按需展开；“少量/短”需要真实走查，不设置未经测量的用时或准确率承诺。

验收AC19覆盖新确诊/无资源，AC20覆盖零核对下仍可获得草稿帮助，AC21覆盖草稿层/接受层/导出状态和更正传播。所有验收当前未执行；DB01可在原型走查或用户纠正后修改。
