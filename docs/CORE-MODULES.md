# 四个重点模块的完整性设计 v0.1

本文件是 SPEC v0.9 的子规格。模块映射：病情 R、指标 M、一图秀 O、临床 C；功能ID见 FEATURE-INVENTORY，验收见 ACCEPTANCE。它们必须作为一期独立可用的完整模块交付。

## 1. 病情整理：从原始材料到可核对的患者档案

**核心问题：** 患者现有材料有哪些、哪些已核对、哪些信息缺失/冲突、复诊时如何带走？

### 二级页面与内容

跨页规则先读 [LOW-BURDEN-WORKFLOW](LOW-BURDEN-WORKFLOW.md)：R05整理草稿和关键疑点允许用户不先核对全部内容就获得帮助；草稿引用与接受记录独立显示，不降低核对语义。

- **资料库（R01）：** 原始报告/图片/PDF/文本；按类型、发生日期、导入时间、处理状态筛选。卡片显示报告日期、机构、页数、原件状态；病理、手术/出院、影像、实验室、分子检测、处方/治疗及其他材料分组。导入、预览、重命名显示标题、关联事件、重新解析、删除/撤销归档均有反馈。
- **报告核对（R02）：** 原件与候选并列；页码/区域/文本定位、原始识别值、归一候选、单位、采样/报告日期分列。可修改、接受、拒绝、留待核对；批量接受先看差异清单，冲突/缺关键语义项不混入一键确认。用户接受表示转录核对，不是专业临床验证。
- **病情档案（R03）：** 原发部位、组织学/分级、FIGO分期及版本/记录日期、手术日期/方式/残余病灶原文、当前及既往方案、疾病评估原文、分子检测。每个字段显示“报告/自述/医生文书/未知”和来源。不同时间的分期/病理记录保留，不用最新值覆盖完整历史；冲突并列待核。
- **指标检测（M01–M03）：** 独立二级模块，详见第2节。报告接受后进入同一观察值库。
- **病情汇总（R04）：** 日期范围、所选材料和缺项清单、治疗/检测摘要、临床/营养/心理讨论问题。支持编辑摘要、预览分享范围、交给Agent或导出，归档版本。缺项提示为准备清单，不要求用户补做检测。

### 关键闭环和异常

设计目标流程为导入→后台任务→可离开页面→完成/失败通知→有出处的整理草稿/少数疑点→用户自选核对或暂跳过→明确接受的记录入档→从草稿/档案打开原文。当前首版已接通明确授权后的 MinerU 转录并本机保存 Markdown 草稿，且可手工核对录入；还没有后台任务队列、自动结构化候选抽取、解析取消/部分成功恢复。扫描件解析不可用时原件保留；“已上传/已解析”不等于“已核对”。按hash提示重复文件；同日同项不同结果不静默合并。原件删除和结构化记录删除分别说明影响。

## 2. 指标检测：正确保存和比较检测结果

**核心问题：** 每个结果是什么、何时测的、在哪里测的、和哪些记录可以放在一条趋势上？

### 结果字典及字段

- 默认展示已存在记录的指标，不显示空白指标墙。首批目录包含CA125、按患者资料启用的HE4、其他由报告明确记录的肿瘤标志物（如CA19-9、CEA、CA72-4）、血常规、肝肾功能、电解质及营养相关化验；通用代谢指标可扩展。目录出现不代表每位患者都需要检测。
- 一条结果包括：指标名称/同义名、样本、数值或文本、比较符、原始/标准单位、参考范围与异常标记原文、采样日期（优先绘图时间）/报告日期、时间精度、机构/方法、原件、处理状态、记录版本。
- 病理/IHC、BRCA/HRD等定性/分子结果进入临床档案，不硬塞入连续数值曲线；它们在时间轴以检测事件出现。

### 操作与呈现

- **检测列表（M01）：** 手动登记或从核对页接受，按日期/类别/机构筛选；编辑、纠正、查看原文、标记不再采用，保留历史。
- **趋势详情（M02）：** 单指标实际纵轴刻度、数据点、同检测来源的参考带（若存在）、同时间范围的治疗节点。支持日期范围、表格视图、点选记录和进入原件；分组依据始终可见。零条引导录入；单条只显示点/表，不伪造曲线。
- **记录质量（M03）：** 缺单位/日期、文本值、检测限结果、重复/冲突、来源失效单独列出；可补充、纠正或保留原样，不能通过隐藏问题让折线“看起来完整”。

### 强约束

采样日期未知可用报告日期作为显示日期，但必须带“按报告日期显示”；仅月份/未知日期留在表格，不虚构日。不同单位/方法先分组；明确可靠的单位换算保留原值、公式版本和用户可见说明。不得把缺失当0、把`<5`当5、把未检测当未检出、把用户确认当医生验证。参考区间只转录/展示，系统不从升降推断复发或疗效。

## 3. 病情一图秀：多条证据在同一时间窗内回顾

**核心问题：** 我何时接受过什么治疗，前后检查、症状和支持记录如何排列，能否在复诊时清晰展示？

### 画布组成

- **O01 时间画布：** 左侧指标清单、日期范围、缩放、治疗/手术/影像事件轨开关；最多选择3项，指标各自独立刻度分面、共用日期轴。选择3/6/12月或全部，点数据点可查看具体值/日期/核对状态/来源，点事件可开原件或临床详情并返回保留筛选。治疗/手术/影像/病理节点共用日期窗；计划与实际使用不同符号。密集事件在轴上聚合并可展开。营养/症状轨作为可选项，心理私密记录默认隐藏。患者选择回顾范围，系统不推导治疗线次/因果。
- **O02 指标卡：** 按卵巢癌患者常见报告类别展示已有CA125、可选HE4、血常规、肝肾/营养相关结果；不堆无记录的空指标。正面为最近值/日期/单位/报告标记，点击执行固定尺寸的3D正反面翻转，背面为最近五次独立刻度小图和日期，重复点击翻回。多个卡片翻转状态彼此独立。减少动效时使用等高、无旋转的正反面切换；卡片不改成点击后在下方纵向撑开的详情区。数据少于两点显示单点/表格，不连线；完整列表可回到指标检测。
- **O03 复诊画布快照：** 把当前时间范围、选中轨道/指标和用户备注保存为快照，可预览并导出到报告。记录筛选和数据版本；从收藏回顾重开快照。导出后源数据变化不悄悄改写旧文件。

### 交互与失败恢复

日期范围/缩放同步所有轨道；点事件打开临床详情，点指标打开检测详情，返回时保持日期/筛选/滚动。默认最多3项数值图以独立刻度分面展示；不同单位不共用无说明纵轴。治疗节点密集时堆叠/聚合，点击展开原始事件。无指标仍可看治疗事件；无治疗仍可看检测，不要求先造完整病程。缺日期事件放“日期待核对”区，不能自动放在今天。

主动开启的待核预览层仅显示分离的候选点/事件，标核对状态和出处，不连入已接受曲线；默认看板/导出仍采用接受记录，分享草稿须另行勾选并保留标签。

一图秀是只读组合视图，数据更正跳转到所属记录，避免再建一份病程数据。移除小胰宝固定20%变化提示；一期不加入未经解释的风险/改善色彩、推断因果或预测曲线。

## 4. 临床：治疗历程、检测档案和临床试验线索

**核心问题：** 已接受哪些治疗、有哪些可追溯的病理/分子结果、准备向医生或研究中心核实什么？“临床”包含临床治疗管理与研究信息两个子场景。

### 二级页面与字段

- **C01 治疗历程：** 方案原文、记录的治疗阶段/线次（可未知）、开始/结束、计划周期、实际给药、手术/住院、暂停/调整及原因原文、药物/剂量/频率原文、机构/医生文书来源。新增/更正、关联检查/报告/症状、查看历史。一次给药属于一个疗程；一次改期保留原计划，不复制成第二次实际给药。毒性自述仅关联时间，不自动归因。
- **C02 临床档案：** 病理与IHC、胚系基因、体细胞基因、HRD分组。保存报告日期、取材部位/标本、方法、原文结果、变异/表达/评分、报告阈值原文、来源。阴性/未检出、未检测、VUS、检测失败、结果待出分别呈现；HRD未知不等于阴性，VUS不自动变成用药依据。不同报告版本并列，医生解释作为单独来源记录。来自R03的字段在此复用，可返回所属记录更正。
- **C03 试验检索：** 关键词、疾病登记词、地区/中心、招募状态、分期等登记条件筛选；列表、详情、登记原文、入排条件原文、联系人（如来源提供）、收藏、加入资料对照。结果排序按用户选择的更新时间/地区等，不按“适合概率”。
- **C04 资料对照：** 用户选中一个试验，将条款原文与已核对资料逐条并列；状态为“已找到相关资料/缺资料/需研究中心解释”。每条显示患者资料版本与来源，用户可标记已向中心核实的日期/回复。Agent可草拟问题并标注生成内容，不给符合/不符合或疗效推荐结论。
- **C05 我的关注：** 收藏条目连同登记快照、收藏日期、个人备注和核实问题；保存源ID，打开时显示最新本地快照与收藏时版本差异。试验结束/撤回也保留旧关注记录，不悄悄消失。
- **C06 数据来源：** 登记平台、登记ID、源条目URL、源更新/采集日期、本地包版本、地区覆盖、更新责任、已知缺失/错误。首次打开说明本地快照不等于实时状态；拟联系中心前主动复核原登记。

### 治疗与研究边界

一期提供人工/报告已确认的治疗史、通用术语解释及试验资料准备，不从基因、IHC或日期自动推出用药/铂敏感分类，也不由患者当前数值排除试验。资料对照是沟通准备工具，不替代医生或研究中心入组筛选。临床治疗、资料对照和病情汇总需要互相链接，但不重复建档。

## 5. 跨模块的理解与讨论帮助

患者可从病情、指标、一图秀或临床详情选中记录后提出“我想弄明白什么”，形成带记录ID/版本、来源和缺项的上下文；不要求重新录入。个人资料解释、临床/营养/心理的可讨论选项和来源规则统一引用 [AI-ASSISTANCE](AI-ASSISTANCE.md)，不得各页自行缩成仅抄录或扩张成处置建议。结果可选择保留到问题清单/帮助记录，随后复用于复诊摘要；默认不修改原始事实或创建治疗安排。

## 6. 四模块贯通的验收例子

卵巢癌模拟材料导入→查看手术/病理、CA125、血常规和分子结果→筛选指标并与化疗/维持治疗讨论/手术节点共同回顾→点值查看来源→打开手术、靶向/维持、复发或放疗沟通话题→保留一个问题到复诊摘要。多个界面必须复用同一记录ID；更正数值后当前M/O/C视图同步，旧导出/对照快照提示旧版。候选不连入正式趋势，私密心理记录默认不进入链路。

以上是规格，不代表功能已经实现；具体数据/接口合同随一期设计细化。


## 7. 工作台设置：配置前先让患者知道数据去向

设置页不属于疾病导航主任务，但为病历落盘、导入和云端解析提供必要配置。全页公共齿轮入口、设置分区、行为状态和凭据/目录边界见 [SETTINGS-DESIGN](SETTINGS-DESIGN.md)。患者资料目录与临床参考数据包分开；所有开关保存到独立草稿，保存成功后才更新当前状态，取消不提交。MinerU 默认使用社区共享凭据状态，不显示密钥；云端发送仍需按文件明确授权。

## 8. 卵巢癌患者照护场景覆盖层

病情整理、指标、一图秀、临床四模块还需共同承接 OVC8–OVC10，不能把腹水、肠功能、造口或遗传报告降成通用“备注”。这些是可选患者任务，不是疾病必经流程。

- **腹部症状与程序记录（OVC8）：** 病情整理接收患者自述与穿刺/引流报告；指标/一图秀允许同时间窗回看体重、可选腹围、进食感受、影像、治疗及程序事件。体重上升可与已记录事件并列，但不标注营养改善或判断原因。程序原文关联时间和来源，患者记录不变成医嘱。
- **术后排便/造口（OVC9）：** 术后支持入口记录排便变化、造口状态/类型/本人困扰与日常影响；无造口时隐藏专属字段，可链接院方/造口治疗师材料并直接形成带来源的问题；不用严重度评分/算法诊断，护理内容不自行生成。
- **遗传报告与咨询准备（OVC10）：** 临床档案分别呈现报告类型和原始分类，连到维持治疗讨论页和自愿的家庭相关问题清单。家属信息不作为一期数据采集目标；算法不输出风险概率、检测建议或家庭通知。

详见 [SCENARIOS](SCENARIOS.md) OVC8–OVC10、[SCHEMA](SCHEMA.md) 第8节、[UI-DESIGN](UI-DESIGN.md) 卵巢癌腹部照护与遗传报告页面补充及 AC33–AC36。症状急症提示、腹围指导、遗传风险表述在专业审核前仅是待审设计问题，不可交付为自动识别或临床建议。
