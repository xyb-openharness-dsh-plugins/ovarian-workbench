# 分期与交付顺序 v0.2

一期保持小胰宝类似范围，二期扩展全程家庭支持；阶段是交付安排，不是患者疾病必经顺序。详见 SPEC v0.8、CORE-MODULES、FEATURE-INVENTORY 与 ACCEPTANCE。

## 0. 当前：一期开发中的合同与首批切片

用户于2026-10-17批准一期开发。HTML v3已作为设计确认基线。v0.1.46包已安装至DSH Desktop App自己的Harness profile；`npm test` 13/13、`npm run check`和`npm run pack:check`通过。安装后未重启当前Desktop进程，真实页面加载待验。已实现本机资料导入与核对、一图秀多指标/时间窗/缩放/共享日期轴/独立翻面卡与所有记录指标卡、右侧可调宽原生Agent、九类临床任务入口、五类卵巢癌治疗沟通情境、临床资料表单、2026登记快照、复诊摘要和五种导出。报告候选支持明确的结果/参考范围/单位表格行并逐条确认；指南仍以来源元数据、官方PDF章节导航与链接呈现，CSCO 2026官方发放/解读活动信息已核实（活动日期不冒充指南出版日期），章节级正文与推荐尚未核验。Desktop实际加载、原生会话、鼠标调宽/系统目录选择器、导出桌面打开仍未验收；CUA可读到DSH Desktop，但当前停留在另一会话；未操作用户会话或重启App。根据Desktop RC服务合同，后端API优先使用`ctx.connection.fetch.register()`，旧profile接口仅作后备。开发顺序按P1任务切片继续，禁止把静态/语法检查写成AC通过。

用户研究与专业审阅可随设计推进：患者走查用于判断负担和可用性，临床人员审核实际疾病术语/解释。二期丧亲家属访谈和家庭法律授权机制不作为一期本机资料原型的前置。正式开放未经审阅的临床解释/服务之前，补齐对应审核与责任人。

## 一期：四核心模块先形成纵向闭环，再覆盖配套功能

| 顺序 | 业务切片 | 依赖 | 可交付的结果 |
| --- | --- | --- | --- |
| 1A-0 | 新确诊无完整档案的帮助导航 | 对应内容/资源审核及宿主只读能力 | F01可只读/暂停、无资源也可准备沟通；个人保存复用1A存储 |
| 1A | 本机资料→批量材料→有来源草稿/少量疑点→自选接受一条指标 | 目录/数据/解析候选合同 | 离线可归档/手填；解析可用时先出草稿，允许全跳过，接受值可回源 |
| 1B | 指标→实际治疗→一图秀→复诊摘要 | 1A及统一记录/版本 | 四模块同源；多轨实际刻度；计划与实际分开；快照可回顾 |
| 1C | 临床档案→试验检索→资料对照→关注 | 1A/1B、卵巢癌登记数据包合同 | 完整检索/详情/对照问题/来源/收藏；无入组结论 |
| 1D | 营养/心理/症状→日历→摘要 | 主体/隐私合同、1A | 三条主轴都能记录、回顾、选择分享；未填不阻塞其他任务 |
| 1E | Agent→归档→五种导出→备份恢复 | 1B/1D；试验任务另依赖1C | 带来源的个人解释/可讨论选项、问题复用和显式发送；五格式真实文件；本机恢复和版本提示 |
| 1F | 跨页/实机/内容审核 | 已完成切片及对应内容来源 | S1–S5走查，AC01–AC16及AC18–AC21证据，包与Desktop实际版本确认 |

所有一期切片在该期内完成；1A/1B可先用于设计验证，不能对外宣称为完整一期。试验数据和PDF/DOCX/JPEG均有独立任务，不能以未接通按钮或来源链接替代已完成状态。云解析可选，人工录入和本地文本流程始终可用；后台任务调度/通知需核验宿主能力。

一期数据/界面边界：默认成人上皮性癌、一个资料夹一个患者；不同主体心理信息分开；不建设远程共享/机构系统。即便专业档案不完整，也可完成基础任务。

## 二期：先支持沟通与资源，再建设敏感权限流程

| 编号 | 内容 | 与一期衔接 | 依赖/完成条件 |
| --- | --- | --- | --- |
| P2-A | 支持/姑息与安宁照护目标沟通 | 延续症状/营养/心理/摘要 | 用户主动进入；本人意愿/联系人可修订；专业内容审核，不推断临终 |
| P2-B | 家属支持资源、预期性/丧亲哀伤与纪念 | 独立家属主体；可无患者资料 | 地区/服务范围/维护日期可见；可不记录/关闭通知；资源无需病历访问权限 |
| P2-C | 临终/去世后的通知与资料生命周期 | 保留已有计划和资料 | 人工明确确认、预览影响、可纠错；暂停相关提醒，不自动删除/开放资料 |
| P2-D | 家属病历授权与共同照护 | 分离患者/照护者/访问者 | 具体授权范围和主体核验、撤销/审计；法律问题按实际地区评审，不假定家属天然有全部权限 |

P2-A/B可先以本机独立功能共创；P2-D不阻塞P2-B。心理/哀伤专业人员和患者/家属参与内容及通知文案审查，资源有维护责任；避免强制哀伤阶段、恢复期限和自动情绪干预。

## 未验证与变更规则

HTML v3为已确认的设计基线；一期实现尚未全部完成，且未做目标Desktop真实操作验收或真实患者/照护者走查。目标Desktop版本、原生会话接入和数据加密能力需分别核验。若某必交付能力延期，需明确改一期范围、记录影响与原因，不能只改验收口径。规格、功能清单和任务共用功能ID，以SPEC为范围主文档、CORE-MODULES为四模块细节、ACCEPTANCE为可观察门槛。


F01无资料先读/暂停/新建主体并保留首条问题，以及R05混合材料全跳过，已在自动化场景验证；这不代表患者走查通过。后续需在目标Desktop检查四模块同源、三主轴、报告预览/核对和导出结果；一期模块未删减，二期任务及范围保持原计划。


开发门槛：交互HTML v3确认后方进入生产代码；用户已授权一期开发。每个切片按已确认场景实现，再复核数据/API合同；不让Tab/流程决定事实表。数据根选择、云端OCR候选与2026研究数据包已有首版代码和自动化检查，分别还欠Desktop系统选择器/真实OCR用户流程、来源覆盖维护及临床审核；其余未验证项见TASKS和ACCEPTANCE，禁止把实现代码等同于验收通过。
