# 卵巢癌患者工作台 UI 设计方向 v0.3

状态：青绿色视觉方向沿用用户参考；本轮将治疗场景与一图秀修订到SPEC v0.7、HTML v3。用户未确认，实际浏览器渲染/宿主预览与患者可用性未验证。

## 用户与体验目标

女性中心、尊重、温暖、有韧性。让患者和家属在长期治疗、安宁疗护及哀伤支持等不同阶段都能找到清晰、平静、可依靠的入口。避免把女性气质简化为粉色、装饰或“积极战胜”叙事；不论治疗状态，界面保持尊严、选择权和可读性。

## 界面语言与组件

- 用清楚、温和、无评判的中文；区分“患者记录”“报告内容”“医生记录”“待核对”“家属支持”。避免“失败”“放弃治疗”等归责词。
- 采用业务整页布局，保留 Desktop 原生会话与公共导航。顶部呈现当前患者资料目录状态和主要任务入口；让临床治疗、营养支持、心理支持三条照护主轴可被看见，并在安宁疗护/家属支持阶段继续提供入口。
- 卡片和时间轴以日期、来源、状态、下一步为主要信息；治疗记录与营养/心理/症状条目可按用户选择折叠，重要信息无需先读长篇科普。
- 使用圆角与轻量留白建立亲和感，阴影克制；图标选用简单线性造型。小巢宝 Logo 仅作品牌识别，不重复做大面积水印。
- 字体优先使用系统中文无衬线字体；支持大字和窄窗口。图表提供表格视图，保证色觉差异用户能分辨数据。
- 安宁疗护、临终照护与哀伤支持页面保持同一设计体系，避免用沉重黑灰视觉暗示死亡，也避免以鲜艳庆祝式表达消费哀伤；由患者/家属共同评审文案和呈现。

## 页面结构草案（按阶段）

### 一期：对齐小胰宝功能范围

八个一级入口统一为：看板、病情整理、病情一图秀、临床、营养支持、心理支持、全程管理、收藏与回顾；设置为公共入口。具体页面以 SPEC v0.7 和 CORE-MODULES 为准。

- 看板用近期任务和临床/营养/心理三条主轴摘要帮助进入任务，不堆满空指标。
- 病情整理：资料库、报告核对、病情档案、指标检测、病情汇总；支持源文与候选对照。
- 病情一图秀：可交互多指标分面、共享日期窗/缩放、治疗手术和检查节点、点选回源；按类别呈现固定尺寸3D翻转指标卡。截图/快照仅在用户确认本期实际交付范围后再实现，原型当前不冒充保存快照。
- 临床：除了临床档案/试验资料，要实际覆盖手术评估与手术后病理、化疗周期、维持/靶向治疗讨论、复发后既往治疗重建，以及患者听到放疗时的情境沟通；不将其排成所有人必经路径。阴性/未检测等状态清晰可辨。
- 营养/心理各有记录、历史、可选讨论与摘要入口；心理私密内容默认不分享，不做打卡积分。
- 顶部资料目录/原生会话两种独立状态；business-first下Agent按需显示，不把0.65误当整页模式的固定占屏比例。

### 二期：安宁疗护与家属哀伤支持扩展

1. 安宁疗护：舒适照护记录、患者表达的照护目标、团队联系信息与沟通清单；不做预后推断。
2. 家属支持：照护者任务、家庭沟通资料、患者去世后由家属自主选择的纪念与哀伤支持资源；不自动推断或量化哀伤阶段。
3. 生命周期与授权：患者生前意愿、经核验的家庭访问和分享、资料导出/保留/删除。

页面树、名称、顺序和可见内容仍需患者/照护者及临床团队共创确认。

## 可访问性与待验证

设计交付前检查文字对比度、键盘焦点、触控目标、大字/缩放、减少动效、读屏名称和非颜色状态表达。制作可交互原型后，在 Desktop 真实容器预览，并邀请不同治疗阶段患者/照护者评审；当前这些检查均未执行。

## 已确认的AI与任务主线（2026-10-17）

提供有来源、结合个人资料的解释与可讨论选项，医疗处置由专业团队确定。优先打通治疗期间日常帮助→持续问题/变化→共同准备复诊；资料和问题复用。具体首页入口、首个触发及信息层级仍待场景讨论，不从这一决定直接推导新导航。


## 双任务入口与信息层级基线（DB01）

看板优先提供“刚确诊，不知道怎么办”“资料很多，帮我理清楚”两个可选入口，不强制用户声明自己属于哪个阶段，完整八模块导航仍可达。不是把专业疾病阶段当首页信息架构。

新确诊路径使用短回应、单次少量可跳过帮助选择、可保存的一小步；无病历/预约/家属/联系人也可只读。避免病情表、所有指标、治疗路线和长科普迎面堆叠，关闭和暂停始终可找。文案不给疗效承诺，不催促积极或填写完整。

混合材料路径先批量收集，再显示短近况草稿、来源/未核对状态和少数必要疑点；默认重点可读，字段表/原文在抽屉展开。草稿/已接受不能只用颜色区分；引用点开即可定位。全跳过后仍可回短整理和问题清单，接受动作不得伪装成“继续阅读”按钮。

一图秀正式层保持接受数据，主动预览待核材料时分轨/分层标识，不与正式线混画；导出预览清楚显示是否选入候选摘录。心理/遗传派生问题继续继承分享限制。

入口文案、最多三个疑点与摘要密度是设计起点，未获患者走查验证；原型必须覆盖无资料/拒绝回答/无资源/全跳过/部分失败，不只展示精美的完整数据看板。


## HTML工作台v2的实际设计（待审核）

色彩沿用青绿#007C80、深青#075B60、柔青#82C9CC、浅青#E9F5F3、暖白#FBFCFA与深墨#243C40。主体系统中文无衬线，标题用较疏字距/中等字重，数据用等宽字体；不捆绑云字体。特征是“先理清一件事”的双任务入口和有出处的短病程草稿，围绕患者精力设计；完整模块留在侧栏。

HTML v1的一图秀实现与SPEC不符：单条静态CA125图、三张空占位卡、点击纵向展开；该版本由用户明确指出需修改，不应作为开发合同。HTML v3补入7项模拟指标清单（按肿瘤标志物/血常规/肝肾营养分类）、最多3项选择、3/6/12月/全部窗口、缩放、各自刻度分面、治疗/手术/病理事件轨开关与可点详情、候选空心点分层、分类指标卡和固定尺寸3D独立翻转。临床治疗页另有手术、化疗、维持/靶向、复发和放疗情境问题入口。数值和事件全是虚构演示；不含真实参考范围/用药数据。O03仍只是页面入口书签，不保存版本化画布快照。

原型只提供明确标注的模拟Markdown下载；五种生产导出、真实AI会话、真实试验/解析均未接入。部分字段为只读模拟展示；原型确认按模块/行为填写PROTOTYPE-REVIEW，不把看到首页等同全部功能确认。真实渲染/截图与窄窗效果需在用户环境核验；模拟DOM逻辑不能代替浏览器实测。


## 工作台设置页

首页与其余页面顶部右侧显示齿轮，具名为“设置”，可键盘触达。参考xyb工作台设置弹层采用清晰分区、固定标题/关闭、内部滚动与固定页脚；窄屏铺满可视区。详细交互、目录与MinerU状态以及凭据安全见 [SETTINGS-DESIGN](SETTINGS-DESIGN.md)。默认状态摘要必须来自同一配置源，状态文字不依赖颜色。

## 卵巢癌腹部照护与遗传报告页面补充

- **腹胀/腹水工作区：** 入口使用患者描述（如“腹胀、早饱或近期做过穿刺”），不可预先诊断为腹水。并列患者自述、报告原文、程序日期与治疗/影像/营养时间线；腹围是折叠的可选记录，需时间、测量位置和“自测”标记。体重升降不自动标色为营养改善/恶化。页面提供可编辑的复诊问题，不提供限盐、利尿或穿刺时机指示。
- **术后排便/造口：** 只在患者选择或材料提及后呈现相关控件；记录生活影响与本人最关心的问题，护理步骤只以有来源、可打开的院方/专业人员材料呈现。出现不适时不运行未经验证的梗阻识别器。联系团队/急诊说明只有在专业审核后启用，并始终可回到本地联系信息。
- **遗传结果与家庭问题：** 以报告原文和实验室分类为首要内容，胚系/体细胞和VUS/未知状态清楚区分。家庭相关内容默认折叠且自愿；不要求姓名/家系图，不自动显示概率、检查建议或分享按钮。展示专业遗传咨询来源和用户可编辑的问题，地区化文案须审核。
- **场景导航：** OVC1–OVC10均按可选任务呈现，不画成所有患者依序经历的漏斗。手术评估、靶向/维持、复发、放疗等既有交互分别保持其原文来源与“不替代团队决策”边界；放疗仍明确标成情境话题。
