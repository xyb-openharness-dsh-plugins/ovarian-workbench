# 卵巢癌患者工作台规格草案 v0.2

状态：**启动设计草案 v0.2；待患者/临床人员共创确认，不是临床决策系统。** 日期：2026-10-17。采用社区 `xyb-workbench-starter` 1.2.1 初始化，业务包尚未实现。

## 1. 问题与最小闭环

目标用户、任务流程和需求假设见 [BRIEF](BRIEF.md) 与 [用户调研](USER-RESEARCH.md)。第一期核心闭环是：导入/登记材料 → 核对结构化候选 → 建立疾病/治疗/支持照护时间轴 → 记录卵巢癌相关指标、营养、心理和症状 → 准备复诊/照护沟通摘要 → 回顾来源和结果。整体分期见 [PHASE-PLAN](PHASE-PLAN.md)，相对小胰宝功能逐项审查见 [FEATURE-REVIEW](FEATURE-REVIEW.md)。

工作台帮助患者面对资料分散、治疗阶段多、指标语境复杂和复诊时间有限的问题。它是患者的资料管理与沟通工具，不诊断、不预测、不分期、不推荐治疗、不自动判断复发或药物适用性。

## 2. 产品边界与设计原则

- 业务整页优先（starter `business-first`，宽度配置0.65）；由 Desktop 保留公共导航、设置、模式和唯一原生 Agent 会话。需在目标 Desktop 版本实测后才能确认宿主合同。
- 主页面候选：总览、病程时间轴、检查指标、治疗历程、症状与生活、复诊准备、资料库、设置/隐私。最终导航和交互需原型共创确认。
- 渐进披露：先展示患者当前可完成任务、最近事件与待办；低频分子检测解释、术语帮助和导出选项折叠呈现。
- 视觉基调：女性中心的青绿色社区支持体验，NOCC 色彩语境与小巢宝标识的运用见 [UI-DESIGN](UI-DESIGN.md)；风格服务于高可读性，不以粉色刻板印象定义女性用户。
- 医疗事实、患者自述、报告原文、系统提取候选、Agent摘要和医生建议必须视觉区分并显示来源/时间；错误可纠正并保留更正记录。
- 未明确地区与指南版本前，不制作治疗路径引擎。2025 CSCO/CSGO 指南只作为内容审查入口，不能据此把国外指南或药品适应症直接映射为中国患者建议。

## 3. 用户旅程与关键页面

### 核心场景

| 场景 | 用户目标与流程 | 一期支持 | 二期扩展 |
| --- | --- | --- | --- |
| S1 初诊建档/多学科或复诊准备 | 汇集病理、分期、手术/影像/实验室和分子检测；核对报告；生成可追溯摘要与问题单 | 资料导入、字段核对、病程时间轴、指标目录、复诊摘要/导出 | 多机构协作及结构化临床审核流程 |
| S2 手术与化疗期间管理 | 记录手术事件、方案/周期/日期，回顾症状和治疗相关检查；安排复诊与化疗事项 | 本机日历、治疗事件、症状/副作用、检查指标、Agent任务与收藏 | 个性化照护计划协作（仍不生成医嘱） |
| S3 维持治疗及长期随访 | 记录维持药物及随访检查，观察由用户选择的指标变化；准备周期复诊 | 治疗历程、指标趋势、报告/摘要、提醒与营养/心理支持记录 | 患者自定随访计划、照护者共享 |
| S4 复发评估与后续治疗 | 整理复查材料与既往治疗史，标出问题，和医生讨论后录入新计划 | 复发相关事件作为医生/报告记录；保留治疗线次历史；提供本地卵巢癌试验线索快照 | 外部数据更新与临床审核工作流；不自动计算铂敏感/耐药或入组资格 |
| S5 临床、营养、心理综合支持 | 让三条支持主轴并行记录，整理症状、进食/体重、情绪/压力和专业支持建议，复诊时回顾 | 三类支持记录与相关待办/来源，用户自愿填写 | 多专业照护计划、转介资源目录、经患者评审的照护者协作 |
| S6 安宁疗护与临终照护 | 记录舒适照护关注点、患者表达的目标、联系人和家庭讨论事项 | 一期仅允许通用症状/生活记录、资料导出和联系信息；不构建临终专属工作流 | 专属安宁疗护页面、患者意愿/目标记录、照护团队协作与家庭沟通支持 |
| S7 去世后家属支持 | 经患者生前授权或家属合法确认，管理家庭纪念资料、访问边界并查找哀伤支持 | 不纳入一期业务功能 | 家属模式/权限转换、纪念资料和经审核的哀伤资源入口；不做自动化哀伤评估 |

### 一期导航与页面闭环

| 页面 | 主要内容 | 关键操作/闭环 |
| --- | --- | --- |
| 总览 | 当前阶段（用户自行选择或引用医生记录）、最近事件、最近指标、临床/营养/心理支持待办、未核对材料 | 打开材料、添加记录、进入复诊准备；不自动生成“病情稳定/进展”标签 |
| 病程 | 诊断、病理、分期、手术、治疗、影像、检测和患者自述的日期流 | 筛选类型/日期；打开来源；修正、撤销或标记待核实 |
| 指标 | CA125与个人选择的HE4/实验室指标趋势 | 手工录入/报告候选核对；显示单位、参考区间和来源差异；不作临床判读 |
| 治疗历程 | 手术与治疗方案/周期、维持治疗、停药/更改、复发后治疗历史 | 记录事件和患者自述副作用；不提供治疗比较/推荐 |
| 症状与生活 | 症状、疲劳、食欲、体重、睡眠、活动、神经病变及患者自定义条目 | 选择性记录、标记希望复诊讨论的条目；不承担紧急分诊 |
| 复诊准备 | 患者选择的时间范围、重要事件、趋势、问题清单、待补资料 | 预览、编辑、导出或交给原生 Agent；生成结果记录来源及生成时间 |
| 资料库 | 原始报告、照片/PDF、解析候选、收藏与导出记录 | 导入、预览、逐项确认/拒绝；本机存储路径与备份说明 |
| 设置与隐私 | 资料目录、锁定/备份、导出、清除本机数据、解析服务告知 | 用户明确选择云端处理前确认发送范围；可取消并保留本地原件 |

一期一级导航、二级页面、各状态与交互需逐项列入 FEATURE-INVENTORY 并经原型确认；此处是范围合同草案。

## 4. 卵巢癌领域数据设计

### 核心实体

- `PatientProfile`：本机患者资料 ID、可选年龄/出生年月、时区、隐私偏好。默认不保存真实姓名/身份证号。
- `Diagnosis`：原发部位、组织学原文/归一类型、分级、FIGO分期及版本、确诊日期、来源。未知值保持未知。
- `ClinicalEvent`：有日期的手术、影像、住院、治疗周期、疗效评价、复发相关记录或患者自述事件；类型可扩展。
- `SpecimenReport`：病理/分子检测报告及原件引用；胚系与肿瘤检测明确分开，保留样本来源、方法、机构、报告日期、原文结果和版本。
- `TreatmentCourse` / `TreatmentAdministration`：方案原文、线次、药物原文、周期/日期、开始/结束/暂停/变更、治疗机构和来源；保留历史，不覆盖旧值。剂量可选且非必填。
- `ObservationDefinition` / `Observation`：可扩展指标目录与观测值。属性包括代码、名称、样本、值、单位、参考区间、检验机构、日期、报告源、核对状态。
- `SymptomEntry`：患者自述症状/副作用、发生时间、持续时间、患者自选严重程度/影响、处理/讨论标记。不映射成CTCAE等临床等级。
- `SupportEntry`：临床治疗沟通、营养支持、心理支持的记录类别；保存记录内容、患者自述/专业人员资料来源、日期、关联事件与希望讨论标记。营养和心理数据不转化为处方或诊断。
- `CareTask`：本机预约、复诊、化疗、检查、营养/心理支持等用户安排；日期、类别、状态和提醒设置由用户控制。
- `SourceDocument` / `ExtractionCandidate`：文件元数据、页码/段落引用、原始文字、候选字段、解析器版本、用户确认/拒绝状态。
- `VisitBrief` / `AgentTaskRecord`：用户选择的摘要内容、时间范围、生成版本、任务指令、会话归档位置和用户采纳状态。

### 事实状态与来源

状态流：`candidate → confirmed | rejected | needs_review`。只允许患者或授权协作者主动确认后进入事实读模型；用户更正保留审计轨迹。事实来源类型：报告原文、用户录入、医疗团队记录、Agent整理。Agent内容始终是建议/摘要，不得伪装为医生结论。来源不可用、冲突或日期不明时明确展示。

### 指标首批候选目录

1. CA125：关注趋势与报告语境；不在工作台设置诊断/复发阈值。
2. HE4：仅在患者实际有检测/团队建议时启用。
3. CBC、肝肾功能、电解质、白蛋白等：通用实验室数值容器，由本地报告/用户提供；不要默认统一告警阈值。
4. 体重、食欲、疲劳等患者自述：与实验室指标区分显示。
5. HRD、BRCA等为报告结果而非普通数值趋势；保存检测类型、样本来源、结果原文、方法和日期。

指标单位必须随记录保存。跨单位转换仅在可靠换算关系明确时提供并保留原值；不同检验机构参考范围不合并为一个“正常范围”。

## 5. 指南与治疗信息治理

- 首版无自动方案匹配器，无药品推荐、风险评分或临床试验符合性判断。
- 如后续做指南浏览库，每条规则需记录发布机构、地区、版本/发布日期、目标组织学/分期/治疗线次、适用限制、证据级别、引用原文、审核人/日期、下一复核日期和下架状态。
- 首选中国CSCO/CSGO公开或授权版本作为中国业务的临床审核依据；NCI/ASCO/ESGO用于国际背景参照，需标明地区差异。
- 治疗方案只保存患者/团队已决定的历史事实；系统展示解释材料时不得将之表述为个体化建议。处方与剂量不得由患者端自动推演。

## 6. 非功能与隐私要求

- 本机优先；患者资料写入用户明确选择的本机目录。SQLite适合跨页面查询、关系和排序；原始文件留在资料目录，数据库保存受控引用和校验元数据。采用递增迁移，不重置用户数据。
- 默认离线工作。云端OCR/解析为显式可选能力，每次首次使用说明文件/字段、接收服务、用途和失败降级；未确认不上传。
- 不持有 FastGPT Key 或其他服务密钥于客户端；如未来接知识服务，按本地或可信服务端能力评审。
- 支持导出与本机删除，导出前预览隐私范围；不默认包含家族遗传信息。
- 时间戳保存时区；日期允许精度到日/月/未知，不能虚构精确时间。
- 大字、键盘操作、窄窗口和减弱动效可用；趋势图有表格等价视图。

## 7. Agent 协作合同

用户可明确选择摘要字段与时间范围，再提交到 Desktop 原生会话。任务快照包含任务目标、所选事实、来源引用、未确认项及“不做诊断/治疗建议”的边界。会话返回内容单独归档为 Agent 结果，默认不回写患者事实。确认回写时要求逐项选择并标记用户确认身份/日期。切换患者资料目录时校验当前项目与会话归属，避免跨患者内容混入。

## 8. 失败与安全状态

- 解析失败：保留文件，允许手工登记或重试；不丢失已核对数据。
- 指标来源冲突/单位未知：并列展示原始记录，暂停合并趋势并解释原因。
- 指南信息过期：显著标注版本和最后复核时间；过复核期限后不用于解释，只提供原始来源链接。
- 云服务不可用/用户拒绝：全部核心资料管理功能仍离线可用。
- 症状严重或疑似急症：提供患者自行维护的联系信息入口；不自动给出医疗分诊判断。

## 9. 验收标准（设计阶段）

- 患者可在不联网、不使用Agent的情况下创建病程记录、核对资料和准备复诊摘要。
- 每个确认事实可追溯到来源/录入者/日期；候选与Agent文字不会混淆为事实。
- 指标趋势保留单位、参考范围、检验日期和机构；系统没有诊断/复发判断标签。
- 治疗时间轴完整呈现手术、化疗、靶向/维持和更改历史，不显示默认推荐路径。
- 患者可以从摘要跳回引用材料，可编辑摘要并在提交给Agent前检查。
- 隐私与解析告知清楚，可取消上传；本机目录和导出/删除路径可查。
- 内容经妇科肿瘤专家审核，导航和记录负担经患者/照护者可用性走查后再进入开发。

## 10. 决策记录与待确认项

- **ADR-01 布局：** 采用 business-first：患者主要任务是查阅/整理病程和时间序列；Agent为按需协作，保留宿主原生会话。待目标Desktop核验。
- **ADR-02 指标：** 采用定义目录+观察值而非固定胰腺癌字段；组织学和治疗语境决定是否使用相应标志物。
- **ADR-03 内容：** 首版做资料管理和沟通摘要，不做指南驱动临床决策；降低过时/误用风险。
- **待患者确认：** 主导航、最优先的复诊任务、哪些症状值得追踪、照护者共享模型、摘要模板和大字需求。
- **待临床确认：** 病理类别与分期字段、分子检测报告字段、指标目录、疗效评价来源、指南版本治理及安全文案。
- **待工程确认：** 目标Desktop版本、原生会话合同、文件解析方式、资料目录授权、SQLite schema/API 与备份/恢复。
- **后续设计交付：** 高精度可交互原型及真实预览、FEATURE-INVENTORY、SCHEMA、API-CONTRACT、数据迁移计划和验收证据。当前不视为已设计或已开发。

## 11. 分期策略

- **一期**：对齐小胰宝现有能力广度，完成本机病程时间轴、日历/待办、报告导入与逐项核对、卵巢癌指标趋势、治疗历程、临床试验本地快照检索、临床/营养/心理支持的轻量记录、收藏与 Agent 任务回顾、多格式报告导出、SQLite本机持久化。详细功能取舍见 [FEATURE-REVIEW](FEATURE-REVIEW.md)。一期不是把胰腺癌字段改名；数据合同按妇科肿瘤重新建模。
- **二期**：完善安宁疗护与临终照护、患者意愿/目标沟通、家属照护协作、去世后家属权限/纪念资料和哀伤支持资源。资源内容需本地化、由专业人员审核，并经丧亲家属共同设计后实施。
- 每期必须独立可用；二期不能作为一期完成的前置依赖。版本门禁和优先级详见 [PHASE-PLAN](PHASE-PLAN.md)。
