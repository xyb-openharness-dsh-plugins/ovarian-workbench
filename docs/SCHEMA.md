# 数据领域模型与可演进合同 v0.1

状态：v0.1可演进合同；代码使用schemaVersion=2的JSON文件仓储，包含文档、候选/核对、临床记录、观察、治疗沟通、营养/心理、问题、安排、收藏、冻结摘要和私密会话回答备忘。患者目录已由用户通过DSH系统选择器指定；选择目录配置单独存放于DSH私有设置区。模型仍可演进；已实现本机文件夹形式的完整备份/校验恢复（恢复到新资料副本，不覆盖原目录）；schemaVersion 1→2迁移已实现，未来版本迁移和Desktop并发走查仍待完成。

## 1. 四层与写入边界

`HTML/正式UI → 页面读模型与命令API → 应用用例/校验 → 领域仓储与文件目录`

UI保存临时筛选/展开/选择，不直接拼SQL或写文件。共享数据只能经应用命令变更；看板、指标、一图秀、临床、摘要读取同一记录及版本。页面可以合并、拆分或重排，领域ID和原始证据保持稳定。不存在dashboard_record、tab_data等页面事实表。

## 2. 核心实体与关系

| 实体 | 稳定身份/关系 | 稳定核心字段 | 易变部分如何处理 |
| --- | --- | --- | --- |
| Workspace/Subject | workspace_id，subject_id；一资料夹一个患者，照护者为不同主体 | 所属主体、别名、创建时间、revision | 页面显示名/布局为偏好，不改病历身份 |
| Document/DocumentVersion | document_id与不可变version_id；属于主体 | hash、受控相对路径、mime、报告元数据、原件状态 | 解析重跑不覆盖原文；ParseRun单独存解析器版本与输出 |
| Evidence/ExtractedClaim | evidence_id，document_version_id与locator | 原文/页码或段落、候选值、类型、subject_id、revision、来源 | 引用证据而非把原文复制进每页；原文变更新建版本 |
| ReviewDecision | decision_id→claim_id/revision | 接受/拒绝/暂跳过、操作者、时间、修订理由 | review_state与临床真实性分开，保存草稿不写接受决定 |
| DiagnosisAssertion | assertion_id→evidence与subject | 原发部位、组织学/分级、分期体系/版本、时间、原文/来源/状态 | 支持多次诊断断言并列，最新显示是可重算读策略，不覆盖冲突 |
| MetricDefinition/Observation | metric_id/definition_version，observation_id；可由support_entry_id链接本人记录 | 值类型、比较符、原/标准单位、采样/报告日精度、实验室/方法、范围/来源、状态 | 普通指标/分类走版本化目录；新语义/新关系才迁移。CA125/HE4与血常规、肝肾/营养相关指标可按目录扩展；患者自报体重保留来源主体与记录链接，不伪装成检验结果；限值/定性不是普通数字；机构/方法不兼容时不能串线 |
| TreatmentCourse/Event | course_id、event_id | event_kind（surgery/systemic_therapy/targeted_or_maintenance/radiation/imaging等受控类型）、计划/提出/实际/取消状态、时间、原文方案/药物/剂量、来源、关联检查 | 显式关系；改期不生成实际给药，阶段/线次可未知；一个事件可增加类型专属字段，但共享稳定event_id/revision/source refs |
| SurgeryDetails | event_id→TreatmentEvent | 术式/目的/手术范围/标本及术后病理、残余病灶描述均保留医生/报告原文，状态、日期、来源 | 不保存软件推算的可切除性或“手术成功”二元结论；报告更正生成版本 |
| RadiationDetails | event_id→TreatmentEvent | 是否仅被讨论/计划/实施、部位/目标/方案/分次的原文、医生记录及日期/来源 | 情境字段而非所有患者必填流程；不能从肿瘤部位自动生成放疗计划 |
| SystemicTherapyContext/AdverseEffectReport | 事件ID/患者主体/引用记录ID | 化疗/靶向/维持治疗用药原文、周期/剂量/时间、暂停更改理由原文；不适自述/影响/报告主体/日期/分享范围 | 自述可与治疗时间关联但不自动建立因果；方案差异不按页面硬编码，使用版本化词典/来源原文 |
| SupportEntry/Question/Task | 各自ID，subject_id、作者/录入者分开；SupportEntry可与派生Observation关联 | 自述/类型/发生时间、privacy、sharingScope、来源、状态、revision；Nutrition记录含食欲、进食困难、本人记录体重kg、估算能量/蛋白质与背景 | UI输入步骤可变；新增字段经过校验并保留定义；删除体重来源记录时原子删除对应派生趋势点；不做诊断或营养处方 |
| Draft/Clarification | draft_id，batch_id，record_refs | 有序来源引用、核对状态、疑点/理由、草稿版本/过时状态 | 是派生读结果，不是第二事实库；未接受引用保留candidate |
| AssistanceResult/Brief/Snapshot | result_id/snapshot_id；input_refs含记录ID/version/state | 问题、来源引用、生成身份/模板版本、主体/分享限制、是否旧版 | 结果不覆盖事实；派生继承候选与隐私，输出重生成新版本 |
| Artifact/Bookmark | artifact_id→snapshot；bookmark_id→对象ID | 真实格式/路径/hash、生成时间、收藏时版本 | 文件登记/缓存不是内容真相；删除原件后引用可提示失效 |
| GuidelineResource/TrialSnapshot | 公开数据包ID/version，与私人事实隔离 | 来源/地区/日期/适用条件/许可/审核、登记ID | 内容/登记更新不迁移患者事实库；缺适用条件不默认匹配 |

`source_kind`、`review_state`、`subject/actor`、`event_status`、`privacy/sharingScope`是独立维度，不使用一个status兼任所有语义。SupportEntry的`sharingScope`为`selectable`（仅在每次摘要/Agent操作中再次勾选后可用）或`private`（仅本人回顾，并从摘要清单、Agent上下文及服务端引用校验中排除）；旧记录缺省按`selectable`读取，保持兼容。日期保存精度/时区；文本比较符与未检测/未知等结果类型独立。身体变化自述可选引用当前主体下的Document；更正按recordRevision校验，并在当前记录保留有限的previousVersions（含分享范围）。症状自述可选保存排便变化、造口状态/类型/本人困扰及日常影响；只有本人选择“有造口”时才保存造口专属字段，选无造口会清空该字段；结构化细节随更正历史留存并由患者自行修正，不代表临床评估。结构化营养记录更正同步其关联体重Observation，分别留存旧版本；撤回错误体重时移除当前Observation，但在营养记录历史中保留原字段。Agent草稿和摘要保留来源版本指针，分享仍由本次选择决定。GUIDELINE-SCOPE定义部位/病理边界。

## 3. 状态、版本与扩展原则

- 领域记录有revision，更新命令带expected_revision；冲突返回可读差异，不后写覆盖。
- 一次接受明确字段组以事务记录review decision与领域写入；幂等键防双击重复。重解析生成新的候选diff，不静默撤销已有接受记录。
- 原始文档版本与正式快照不可变，当前读视图可重算；源更正触发相关草稿/解释/摘要“需重新核对”，不改旧导出。
- 隐私和候选状态跟随来源依赖，派生合并采用更严格分享限制；去掉原文不能去掉其问题/解释中的敏感前提。可改写不预设事实的问题但需保存生成来源。
- 有界扩展：扩展schema_id/version、数据类型、验证/单位目录与允许键；核心外键/排序时间/状态需结构化，不靠任意JSON和模型猜字段。
- 枚举版本兼容：未知代码保留原文并可显示“暂不识别”，不在旧客户端静默丢数据。布局和模块排序只改UI偏好/读模型，不能变更领域事实。
- 不为“以后可能有所有功能”做全量事件溯源/图数据库；SQLite＋稳定ID＋必要修订历史足够，是否增加索引以测量决定。

## 4. 数据与API合同的演进

工作流若需要持久恢复，保存最小任务实例ID、definition_version、当前步骤及已选/跳过/取消的事实、transition_reason与时间；它不是临床事件。新增/插入步骤要给旧实例继续/重开策略，不强制在当前实例重填旧资料；并行任务按独立ID与依赖引用，不用页面索引定位。当前一期先用明确任务命令与最小恢复状态，不引入通用工作流引擎。

页面读模型显式schema_version：overview/record-list/metric-series/one-page/clinical/draft/brief。它们共享record_refs，不允许返回“没有出处的最终病情字符串”替代可核对记录。具体URL/宿主service调用名须核验后冻结，见API-CONTRACT。

改变UI层级、字段顺序、从问答变上传优先：无需迁移。增加普通指标：新增目录定义；新增原发部位映射：版本化字典/内容适用映射。新增真实领域关系或语义：递增迁移并说明兼容、备份、失败恢复和旧客户端策略。破坏性变更不能以清库实现。

## 5. 文件/事务与恢复

生产资料只在用户选定根内，存稳定ID/相对路径/hash；系统目录选择器取消不落盘，服务端校验目录可访问且可写；更换目录需确认旧资料保留且不迁移。设置页可将workspace-v1.json、引用原件和转录文件复制到用户选定备份位置，manifest记录每个相对路径、长度和SHA-256。恢复先核验manifest、记录和所有被引用文件，再在用户选定目录下创建临时副本、逐文件校验并原子改名，最后切换工作区；旧工作区保留。上限为5000个文件、总计2GB、单文件20MB；schemaVersion不兼容、清单/哈希错误、缺失文件、超限或恢复失败均不改变当前工作区。原件使用随机文件名和相对路径，禁止任意路径读取。JSON状态以同目录临时文件+原子rename提交；schemaVersion 1→2迁移前保留权限0600的原JSON副本。完整备份包含被引用的原件、转录和历次迁移副本；恢复后逐文件验hash并检查来源引用、主体、版本。数据库和导出/解析文件生命周期分开，删除需展示受影响记录，不能显示已不存在原件可读。

原型只有内存模拟，不将prototype state或静态fixture直接复制为生产表。正式摘要为不可变快照；编辑从当前来源记录创建递增版本并保留previous_snapshot_id，回收站使用可恢复状态而不物理删除。UI确认不等于模型冻结；正式实现前审核查询、关系、事务与恢复，保留API兼容范围。

## 7. 工作台配置与患者病历隔离（候选设计）

配置是工作区/安装主体级数据，不是患者临床事实；所选患者目录引用单独存储于DSH私有配置区，实际病历只在用户选择的资料根内。可演进的 `WorkspaceSettings` 只保存：版本、所选患者资料根目录引用/状态来源、解析模式、云端同意记录的目的/范围/版本/时间、自备凭据的安全存储句柄或外部来源状态、临床数据包根目录/包版本引用、显示偏好和更新时间。凭据明文不得进入SQLite病历、配置API回包、日志、导出或原型；默认共享MinerU密钥由受维护的运行时社区凭据提供器给出，只保留来源和当前可用状态。

患者资料路径、工作台服务配置路径和临床只读数据包路径分别建模；从“表单是否存在路径”推断“存储已可用”禁止。目录检查是状态事件，配置revision与目录初始化/迁移进度分开。更新数据包保存来源、地区、版本、覆盖、manifest摘要、校验/导入时间、失败状态；不把数据内容复制进病历对象。

可演进验收：设置表单重新分组不迁移病历；增加解析模式不重置云端同意；更换目录默认保留旧目录/不可隐式合并；社区凭据轮换不修改患者记录；新增临床数据包版本可并存、回退并保留来源；失效路径下旧配置仍可恢复。正式表结构/凭据存储方式待目标Desktop能力和安全合同核验后冻结。

## 8. 卵巢癌照护扩展候选（领域语义先于页面冻结）

为支持腹水/穿刺、术后肠功能与遗传报告相关场景，建议以稳定ID与来源引用扩展，不以单一页面表单定型：

- `SupportEntry` 可通过版本化 `entry_kind` 承载患者自述的腹胀、进食影响、排便变化、造口生活影响；结构化字段仅限有清晰单位/定义且经审查的项目。腹围是可选观察值，保存测量位置/时间/录入者/自测来源，不要求连续测量，也不推断临床状态。
- 新增 `ProcedureRecord` 候选，关联 `TreatmentEvent` 与原始文档，涵盖穿刺/引流等程序的报告原文、日期精度、机构和来源定位。结构化放液量/性状只有在文书明确、单位可识别时保存；同日多次程序各自独立，绝不把患者记录当成手术/护理医嘱。
- 新增 `GeneticResultContext` 候选，引用原报告，分别记录样本/检测类型、基因、报告原文、报告方分类和未知状态。家属身份、家系关系、患者是否告知家人不纳入一期必需模型；如将来有需求须独立权限、同意和隐私评审。
- 造口和排便自述可继续存为主体私有的 `SupportEntry`，允许结构化扩展，但不能预设所有术后患者都有造口，也不引入自动严重度/病因评分。每条记录可设为仅本人回顾，或仅在患者每次显式勾选后进入摘要/Agent候选；此范围与当前记录页面可见性分开。

以上是待原型与临床/隐私评审的数据语义候选，不等于已冻结的DDL。显示页面重排不得改变这些来源、主体、核对状态和时间语义；紧急提示不由这些记录在客户端自行判定。


## 9. 会话回答备忘（schemaVersion 2）

`AgentResponse`由患者手动从DSH原生会话复制后保存；它是私密的未核验备忘，不能作为Observation/ClinicalRecord，不进入复诊摘要或后续AI上下文。可关联指标、治疗事件、营养/身体自述或复诊问题，并冻结保存时record revision与标签。状态`user_checked_references`只表示用户查看过来源对应关系，不代表临床核验。关联资料后续被修改或删除时，备忘保留当时引用和修订号，提醒用户回原记录复查；当前版本不自动读取原生会话或验证模型回答。
