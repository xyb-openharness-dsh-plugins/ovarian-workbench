## 1. 产品目标与范围决策

帮助新确诊的患者与照护者先获得被理解的回应、可读懂的信息和眼前下一步沟通导航；在治疗期间理解检查和治疗、梳理进食或心理困扰，并把持续积累的变化与问题转成复诊沟通材料。用户已确认优先结合“日常理解与照护＋共同准备复诊”，两者共享资料、记录和解释结果；家属代管仍是支持方式，不是本轮新增的独立优先主线。临床治疗、营养支持、心理支持是本产品三条并列主轴；一图秀负责把这些记录放回同一病程语境。

一期拟覆盖成人上皮性卵巢癌、输卵管癌及相应上皮性原发性腹膜癌的资料与照护记录。这是三个不同原发部位、同一相关诊疗框架，不是“卵巢癌的三种类型”；卵巢的组织学类型另行记录，腹膜转移不等于原发性腹膜癌。范围依据国家卫健委《卵巢癌诊疗指南（2022年版）》第1页；CSCO卵巢癌诊疗指南2025确已发布，但本轮未取得其全文逐条核验，因此不得把2022版说成当前最新治疗依据。指南来源、分类逻辑、覆盖外处置和发布前逐章节核验要求见 [GUIDELINE-SCOPE](GUIDELINE-SCOPE.md)。首要用户是卵巢/输卵管/原发腹膜癌患者及其照护者；非上皮性肿瘤、交界性肿瘤、转移瘤和未明确原发/组织学的材料仍可归档，但不得套用上皮性癌的专属解释或决策选项。

默认面向中国大陆简体中文使用场景；国际资料只作明确标注地区的参考。技术性设计可以继续推进；临床解释内容、真实用户资料接入和正式发布分别按对应能力核验，不能用未完成访谈阻断所有设计工作。

整体愿景覆盖支持/姑息照护、安宁疗护、临终和去世后家属支持。它们不能被建模为“治疗失败后才开启”的固定顺序。支持/姑息照护可与抗肿瘤治疗并行；临终照护和去世后家属模式采用单独的工作流。产品分期不代表临床照护必须分期。依据及限制见 [USER-RESEARCH](USER-RESEARCH.md)。

一期AI价值已于2026-10-17由用户确认：提供有来源、结合个人资料的解释与可讨论选项，帮助理解和准备决策；医疗处置由专业团队确定。具体任务、来源/缺项与结果验收见 [AI-ASSISTANCE](AI-ASSISTANCE.md)。这是已确认产品要求，尚非用户效果或医学内容验证。

## 2. 一期与二期的明确边界

**一期必交付：** 病情整理、指标检测、独立一图秀、临床治疗与试验资料、营养支持、心理支持、全程安排、收藏/回顾、五种报告导出、本机存储和原生 Agent 协作。保留小胰宝类似的功能广度，重建卵巢癌领域字段；每项都有空/加载/失败/恢复状态，详见 [FEATURE-INVENTORY](FEATURE-INVENTORY.csv)。

**二期工作清单：** 专属安宁/临终照护沟通、患者意愿、家庭权限、照护者支持、预期性哀伤及去世后家属支持。先建设本机、自愿使用、无需患者资料的支持资源入口；跨账号共享和去世后资料授权为独立增强项。资源入口不应被家庭权限工程整体阻塞。

一期的试验检索是正式能力。卵巢癌数据准备、来源和更新责任单独列为发布依赖；2026多来源研究快照现存于 unified_search_trials/research/ovarian-cancer；ClinicalTrials.gov为指定条件下的API结果，ChinaDrugTrials与ChiCTR为部分覆盖，仅供设计/调研参考，尚未集成进产品或完成正式来源覆盖。数据未就绪时界面可以降级到原始来源，但这种降级不能被登记为“本地检索已完成”。五种导出均需真实文件验收，不能只交HTML/Markdown后宣称一期等同小胰宝。

## 3. 用户场景与导航

新增直接需求材料E03（报告/治疗混杂与精力不足）和E04（新确诊的情绪/行动迷失），详见 [PATIENT-JOURNEYS](PATIENT-JOURNEYS.md)。用户要求继续完成后，采用DB01低负担设计基线：先提供有出处的未核对整理草稿，只问少数影响当次理解的疑点并可跳过；Q4没有独立明确答复，DB01是设计者可修改的方案，不标为用户已确认。已接受记录/正式趋势与草稿层仍严格区分，完整规则见 [LOW-BURDEN-WORKFLOW](LOW-BURDEN-WORKFLOW.md)。

完整触发、输入、步骤、产出和恢复见 [SCENARIOS](SCENARIOS.md)。

卵巢癌核心治疗任务不能只写成通用“记录治疗”：一期设计须可走查初次手术评估/新辅助治疗与间歇性减灭术沟通、手术后病理与残余病灶理解、含铂化疗周期准备、维持/靶向治疗讨论、复发后治疗史重建，以及患者听到放疗时理解其目的和需核实的问题。场景见SCENARIOS专项表；界面只帮助患者整理证据和准备问题，专业团队决定治疗。放疗必须按低频/特定情境呈现，不能画成卵巢癌人人经历的标准步骤。

HVT回应进一步将腹胀/腹水及穿刺材料（OVC8）、术后排便/造口生活影响（OVC9）、遗传报告后的自愿咨询准备（OVC10）列入一期**原型设计覆盖**，与患者病情、指标/一图秀、临床和支持模块贯通。对应设计要覆盖触发、低负担步骤、可回顾产物、异常/退出恢复及医疗边界；生产实现范围仍须用户按具体HTML模块确认。急症提示、专业护理和遗传咨询内容在来源与临床审核完成前不提供指令性文案。

看板先提供“刚确诊，不知道怎么办”和“资料很多，帮我理清楚”两个可选择任务入口，分别承接F01/R05，完整导航继续可达；入口文案和信息密度待原型走查。

导航是任务入口，数据不按页面重复保存：病理/分子结果从病情档案进入临床档案；指标同源进入指标页和一图秀；实际治疗事件同源进入临床、病程和摘要。复诊准备位于病情汇总，并可从看板直接进入。

## 4. 临床、营养、心理三要素的实际功能

临床治疗必须支持卵巢癌患者真实会碰到的材料与讨论：妇科肿瘤团队对初次减瘤手术可行性的评估、初始手术或先系统治疗再间歇手术的历程、手术范围/病理/残余病灶原文、术后或围手术期化疗、维持/靶向用药及分子检测背景、复发后既往治疗与再次手术/系统治疗讨论。记录方案/原文、治疗目的（按医生原文）、阶段/线次、计划与实际周期、药物及剂量原文、暂停/更改原因、手术/放疗报告和不良反应自述；手术评估、分子背景和治疗时间可以帮助准备沟通，绝不由应用自动选择方案或判定药物适用。

放疗不是一期患者流程里的默认步骤。若患者因局部病灶、症状控制或医生提出的其他特定理由听到放疗，可查看“为什么会讨论、照射部位/目标在医生记录中如何描述、预期目标/替代方案/副作用应问什么”的沟通准备页；不能暗示其为常规根治/辅助路线，也不判断是否应做。NCI专业资料说明复发性卵巢癌放疗作用尚未明确，且该资料不是中国指南；具体内容需按最新中国指南、患者场景和专业审核维护。

营养支持保留日期、体重、进食较平常的变化、进食困难/相关症状、可选能量与蛋白质、营养制剂用量和专业建议原文。任一项即可保存；缺失不按零计算；估算量需标“患者估计”。体重可以关联腹水、水肿或引流事件，避免把体重升高标成营养改善；不自动生成热量目标、处方或诊断。通用血糖/代谢记录可按实际需要启用，去掉的是胰腺癌专属PEI等默认流程，并非禁止记录通用指标。

营养支持二级导航为“当下困扰 / 进食与体重 / 建议与回顾”：患者可从早饱、恶心、腹胀/排便、体重变化或既有专业建议进入；记录胃口、困难、体重、背景、可选本人估算能量/蛋白质；另行转记专业建议、制剂名称及实际使用情况。每条可查看、删除，并由患者主动选择是否整理为复诊问题。采用可跳过字段；缺失值不按零计算，估算量需标注本人估算。体重可关联腹水、水肿或引流背景，不自动生成营养结论、摄入目标或处方。

心理支持二级导航为“当下感受 / 我的记录 / 支持资源 / 身体与亲密”，涵盖手术后身体形象、绝经/生育顾虑、亲密关系/性健康、与家人沟通。允许私密记录情绪、睡眠、困扰、想获得的帮助和已获得的专业支持；采用可跳过的主观描述，不以坚持记录/积极程度打分。照护者代记需标识，照护者自身的心理记录归属照护者，不能作为患者症状。私密内容默认不进入一图秀、Agent快照或任何导出；只有记录主体对具体内容明确授权后才分享。派生解释/问题/回复继承主体和分享限制，本次解释授权不自动延伸到共同复诊或导出。支持资源上线前须核验服务方、适用地区、开放时间和联系方式。

收藏与回顾二级导航为“问题清单 / 已保留结果 / 报告与任务”：问题可从报告、治疗、营养、身体感受或患者自述添加；已保留结果须明确是页面入口、内容快照还是来源版本，原型目前仅收藏一图秀入口并在打开时读取当前数据，不伪装成固定快照；报告列表可回源，个人安排与临床事件分开。

一图秀将患者本人或照护者代记的症状感受作为独立轨道，与检验指标、治疗事件分层呈现。患者可只记当天最想讨论的一项，主观等级 1–3（轻/中/明显）的锚点由患者走查确认；空白不补 0，不要求每日打卡，不自动推断原因、治疗毒性、病情变化或紧急程度。代记需保留记录者与记录主体，患者症状不得混入照护者自身健康记录。该轨道属于低负担沟通辅助，范围和字段以患者走查后定稿。

三条主轴共享“提出当下困惑—选择相关资料—带来源解释—呈现可讨论选项/缺项—选择保留的问题—持续回顾—复诊摘要”的闭环。记录与导入是输入方式，患者可以只提问或只用现有资料，不要求填完日志才获得帮助。可记录专业人员已给的建议及其日期/来源；未建成的转介、诊疗或危机服务不显示可承诺服务的按钮。

## 5. 事实、核对和数据模型

数据层独立于Tab/页面布局和流程步骤：稳定领域/证据/主体/版本关系为事实源，前端经命令API和版本化读模型交互；页面重排不改事实库，流程先后变化不重建档案。候选模型、关系/修订、扩展/迁移和演进验收见 [SCHEMA](SCHEMA.md)，职责接口见 [API-CONTRACT](API-CONTRACT.md)。HTML确认前仅MockAdapter/设计合同，不实施生产DDL或把原型state存为业务真相。

“用户确认”仅表示已核对录入/采用，不能显示为“医学已证实”。采用两个独立维度：

- 处理状态：`candidate / accepted / rejected / needs_review / superseded`。
- 来源：`report_transcription / patient_reported / caregiver_reported / clinician_documented / agent_generated`；另存录入者、记录主体、来源文件/页码和核对时间。医生来源只表示引用医疗文书；无核验流程不标“医生审核通过”。

未核对候选可以用于有出处、明确状态的整理草稿与一般解释，但不自动进入已接受档案/正式趋势。关键个人背景尚不确定时不据此筛选个体处置选项，草稿层/图表预览/分享见LOW-BURDEN-WORKFLOW；从候选派生的解释和问题同样继承核对状态，不能经问题形式进入默认分享而伪装已知事实。用户可以不核对而先获得整理和问题准备帮助；接受动作仍逐项或按明确字段组进行。

Agent摘要即使被采纳仍保留生成来源；只有逐项摘取到原报告并核对的字段才可建立报告转录记录。源记录更正后，读视图更新；既有摘要/试验对照快照保留原版本并提示“相关资料已更正”。

| Diagnosis / MolecularFinding | 病理/分级/分期及版本原文、检测报告ID/日期；胚系/体细胞/未知、样本、方法、结果原文、变异分类；HRD保存方法/分值/阈值原文，不跨报告推算 |

| TreatmentCourse / TreatmentEvent | 方案ID、药物原文、计划/实际日期、状态、周期、线次（可未知）、用药/手术/暂停/变更、来源；计划完成不自动等同实际给药 |
| SurgeryEvent / RadiationEvent | 复用TreatmentEvent身份与版本；手术按原文记录目的、方式/范围、日期、术后病理/残余病灶描述/报告引用；放疗记录是否仅被提出/计划/实施、照射部位/目的/方案原文、分次/日期和来源；不推断手术可切除性、治疗适应证或疗效 |
| TherapyContext / AdverseEffectReport | 患者可引用医生记录的化疗/靶向/维持治疗背景和药物原文；不良反应自述单独记录主体、日期、描述/对生活影响、来源和可分享范围，可关联但不自动归因药物 |
| NutritionEntry / MoodEntry / SymptomEntry | 日期、主体、录入者、自述内容/可选量、来源、隐私/分享选择、关联事件；症状不自动归因于某种药物 |
| CareTask | 本机计划日期、类别、说明、状态、关联事件；无宿主后台能力时只提供打开工作台后的待办 |
| TrialRecord / TrialReviewSnapshot | 来源/登记ID、登记状态、更新时间、中心/地区、条件原文；对照使用的患者记录版本、待核实问题，不保存适合入组结论 |
| VisitBrief / Export / AgentTask / Bookmark | 所选记录ID和版本、过滤范围、生成时间、隐私选择、文件/会话引用、任务状态；重复导出生成新版本 |

SQLite保存事实、索引和版本；原始文件写入用户资料目录并受控引用。明确复制导入与原路径链接两种模式的丢失/删除语义后再实现，默认复制到资料目录；文件导入与数据库写入失败需清理临时文件并允许重试。删除原件前说明受影响引用，不能删除原件后继续显示“可追溯原文”。迁移失败保留旧库与备份。

## 6. 指标呈现与一图秀规则

指标保留报告给出的参考区间、异常标记和原文，显示“报告标记”而非系统诊断。允许在同单位、同方法/可比机构内显示参考带；不由软件设定临床诊断或复发阈值。

定性结果、未检出、未检测、检测失败、待出结果、未知和数值零必须分开。`<5`不转成5，检测限值不连入普通精确值折线。缺失单位/精确日期保留在记录表中，标注暂不连线原因；不同单位/方法分组或并排图，不能静默归一后共用无说明的纵轴。

一图秀是独立、可操作的复诊沟通画布，不能退化为页面拼贴或单张静态图：指标清单多选（默认最多3项，必要时分面）、近3/6/12月/全部日期范围、时间缩放、治疗/手术/影像检测节点开关及点击追溯；指标、事件轨共用日期窗。不同单位/方法各用独立分面与实际刻度，不能共用无说明的纵轴。图表随筛选变化更新；点/事件可键盘访问、查看值/日期/来源并往返原件。指标趋势卡按类别组织，每张卡真实正反面叠放并独立翻转，尺寸稳定；减少动效或窄屏时提供等价静态展开/列表替代。卡片显示最近值、日期、单位、原报告标记，背面为最近五次小趋势并能去全部记录。不得用升降颜色冒充病情结论，不复制固定20%警示。待核候选只在主动打开的独立图层显示，不与已接受值连线；数据少于两点时不画曲线。具体状态、缺数据降级和回源见CORE-MODULES与UI-DESIGN。

## 7. Agent、指南与外部能力

原生Agent提供一期核心帮助：基于所选个人资料进行通俗解释、列出有证据支持且仍需专业团队确认的可讨论选项，辅助患者理解和准备决策；同时支持病程摘要、问题草拟和试验资料对照。不能把选项相关性等同于个体适用性确认。解释结果区分个人资料依据、医学知识来源、通俗解释、可讨论选项及信息缺口；每条实质性医学解释/选项可回到其来源，个人事实可回到记录版本。来源需标地区、版本/日期和适用限制。不能根据病理/分子结果自动推荐个体药物、剂量、入组资格或预后。

Agent快照先预览所选记录/图片与目的；默认不附全量病历、家族信息或私密心理内容。支持仅创建草稿、保留宿主已有草稿并显式发送；切换患者目录后旧任务快照失效。云解析同样按选中文件/批次告知接收方、发送范围和本次授权，服务或范围变化重新确认。保留人工录入和本地文本路径。

一期的指南支持是可信资料链接、术语解释的来源和医生已决定方案的引用，不实现自动路径引擎。先前找到的2025指南只证明当时可见版本，不能在2026年标“最新版”；临床内容发布前核对实际版本、地区和适用人群。试验数据包保存采集日期、登记更新时间、同步错误及来源链接；用户每次拟联系中心时复核原登记和中心状态。

## 8. UI、宿主与运行能力

用户明确要求：先交付可打开、可点击的HTML工作台，确认对应版本/模块后再生产开发。当前设计原型 [workbench-v3.html](prototype/workbench-v3.html)，状态/预览限制/确认范围见 [PROTOTYPE-REVIEW](PROTOTYPE-REVIEW.md)。本轮无业务后端/数据库实现，原型模拟不等于实际能力。

采用 `customFrame` 业务整页模式，首次进入不自动创建会话。首页/顶部右侧“AI 对话”入口在用户主动请求时恢复或创建归属本工作台的会话，并将 DSH 原生 `conversation` 节点显示在**工作台右侧**；工作台保留在中间主区域。右侧面板有独立隐藏/重开按钮和可拖动分隔条（初始宽度35%，允许范围25%–45%；不挤压业务内容，窄窗时折叠成右侧抽屉/覆盖层）。隐藏不删除会话、不清除工作台筛选/草稿。基于本人选中的记录生成讨论草稿，经明确告知和同意后带入 DSH 原生输入框；一键发送仅在用户确认本次发送内容后进行。用户可继续在原生输入框互动。若已有任何原生草稿、附件引用或提交状态，拒绝合并/覆盖/发送；支持复制到剪贴板备用。未提供提交API时只填草稿并提示改用原生发送控件。宿主回答不会自动回写业务资料。会话没有时只在用户点击AI入口后按受支持API创建一次并绑定当前工作台；重复点击复用。取消或创建失败不生成重复会话/目录，保留业务状态。资料目录状态与会话绑定状态分开显示。详细UI/状态验收见 [AGENT-PANE-DESIGN](AGENT-PANE-DESIGN.md)。

小巢宝正式参考为用户提供的 `assets/brand/xiaochao-community-logo.png`；starter的 `xyb-logo.png` 是机器人，不能当作小巢宝Logo。青绿色基调、暖白背景、大字、键盘、非颜色状态及减少动效见 [UI-DESIGN](UI-DESIGN.md)。长弹窗固定标题/关闭，内容区滚动；一图秀窄屏允许滚动或分面，不压缩文字使其不可读。

一期不承诺加密、系统锁屏联动、后台通知、远程共享或远程撤回已导出的文件；这些需能力核验。提供本地数据位置、明确分享预览与备份/恢复流程，不把“本地存储”描述为自动加密或完全不会外传。
