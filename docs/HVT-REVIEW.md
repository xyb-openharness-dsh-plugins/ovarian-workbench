## 4. 差异评价

### B1 腹水与腹胀（OV-02）

- **现象**：全文没有以腹水为触发条件的患者场景。`腹水` 在 `docs/`（排除 `_archived/`）命中 8 处、7 个文件，全部是别的主题的注脚：营养章节"体重可以关联腹水、水肿或引流事件，避免把体重升高标成营养改善"（`SPEC.md:55`）、范围声明（`GUIDELINE-SCOPE.md:9`、`GAP-ANALYSIS.md:7`）、研究综述（`USER-RESEARCH.md:32/89`）、审核记录（`REVIEW.md:20/40`、`FEATURE-REVIEW.md:11`）。SCHEMA 没有腹围、穿刺、引流字段；ACCEPTANCE 27 条无腹水条目。
- **证据**：`grep -rnE "腹水" --include="*.md" .` → 排除 `_archived/` 与本报告后 8 处，无一是患者任务；`SCHEMA.md` 实体表（13–29 行）无引流/穿刺实体；`ACCEPTANCE.md` 无条目。
- **影响**：腹水是卵巢癌患者最常见的困扰之一（腹胀、吃不下、平卧困难、反复穿刺）。更严重的矛盾是：**SPEC 承诺"体重可关联腹水/引流事件"，但数据模型里没有这个事件**，实现者只能塞进自由文本，之后无法在趋势上解释"体重为什么突然降了 2kg"。
- **处置**：补丁 P1。

### B2 肠梗阻（OV-03）

- **现象**：`肠梗阻` 在 `docs/` 内 **0 命中**。卵巢癌腹腔转移导致肠梗阻是患者最需要"不要在家等"的情形之一，文档没有任何入口、症状组合或联系条件。
- **证据**：`grep -rnE "肠梗阻" --include="*.md" .` → 0；`grep -rnE "排气|排便" --include="*.md" .` → 仅 `SCENARIOS.md:81`（术后"记录伤口、排便/进食"，属术后恢复，不是梗阻识别）。
- **影响**：会做成"症状都能记，但记了不告诉你要不要紧"。这类缺口的代价不是体验差，是延误。
- **处置**：补丁 P2。

### B3 造口与盆底肠功能（OV-09）

- **现象**：`造口` **0 命中**。减灭术可能涉及肠切除与造口，术后排便改变（次数、急迫、失禁）是长期困扰，文档只有 OVC2 一句"记录伤口、排便/进食"（`SCENARIOS.md:81`）。
- **证据**：`grep -rnE "造口" --include="*.md" .` → 0；`grep -rnE "盆底" --include="*.md" .` → 0（均排除 `_archived/` 与本报告）。
- **影响**：造口照护是高频日常任务（换袋、渗漏、皮肤），且与"能不能出门"直接相关；缺它会让术后模块看起来只有"病理看懂了吗"。
- **处置**：补丁 P3。

### B4 遗传咨询与家系（OV-10）

- **现象**：胚系/体细胞 BRCA 的区分写得很清楚（`ACCEPTANCE.md:13` AC07、`SCENARIOS.md:97` OVC4），但**没有"这个突变对家属意味着什么、要不要让姐妹去检测"的患者任务**。`家系` 在 `docs/` 内 0 命中。

## 5. 需求补丁

### P1 腹水与腹胀 → 并入 `docs/SPEC.md` §3（场景）与 `docs/CORE-MODULES.md`，新增 OVC8

> **触发。** 腹胀明显加重、吃一点就饱、裤腰变紧、平卧气短、体重短期内上升或下降；或刚做过腹腔穿刺/置管。
>
> **交互。** 记录腹围（同一位置、同一时间点，标注自测）、体重、进食量变化、平卧是否气短；记录穿刺/引流（日期、放液量、性状原文、机构、术后感受）；把这些记录与影像、CA125、实际治疗放在同一时间窗。
>
> **产物。** 一份"腹水相关近况"，包含变化曲线与"下次复诊要问"（是否需再次穿刺、引流管护理、饮食与活动注意）。
>
> **边界。** 不根据腹围或体重推断腹水量、不判断是否复发、不给利尿剂或限盐建议、不给穿刺时机建议；引流管护理只转录院方原文。

**判据**：`SCHEMA` 新增 `ParacentesisRecord`（日期精度、部位、放液量、性状、机构、来源）；`SupportEntry` 增加腹围字段或复用 `Measurement`（协议=腹围，含测量位置）；`ACCEPTANCE` 新增一条覆盖"体重上升但有腹水记录时不标营养改善"与"同日两次引流"。

### P2 肠梗阻与急症边界 → 并入 `docs/SPEC.md` §3/§9

> **症状组合。** 把"腹胀痛 + 停止排气排便 + 呕吐 + 无法进食"作为一组常显短语，出现在症状记录入口与腹水页；命中该组合时显示"这可能是需要当天处理的急症，请立即联系治疗团队或急诊"，并注明这是帮助信息、不是分诊。
>
> **不做什么。** 不判断梗阻部位或程度、不建议进食/禁食、不给等待时间。

**判据**：`ACCEPTANCE` 新增一条：无网络、无模型时该提示仍常显；文案经专业审核后才可上线（当前标 U）。

### P3 造口与盆底肠功能 → 并入 `docs/SPEC.md` §3 与 `docs/CORE-MODULES.md`（术后/长期）

> **造口。** 记录造口类型（结肠/回肠，原文）、换袋频率、渗漏与皮肤问题、饮食与气味困扰；提供"回纳讨论要问什么"的问题清单；护理步骤只引用院方/造口治疗师原文。

### P4 遗传家系沟通 → 并入 `docs/SPEC.md` §3 与 `docs/SCENARIOS.md`，新增 OVC9

> **触发。** 报告显示胚系 BRCA1/2 或其他胚系致病变异（含 VUS 需区分）。
>
> **交互。** 用一页说明"胚系 = 可能来自父母、可能传给子女"，区分胚系与体细胞；给出"可以问遗传咨询门诊的问题"清单（是否需复核、哪些家属适用、检测流程与费用、对保险/就业的影响如何咨询）；记录患者是否已告知家属（只记"已告知/未告知/暂不想"，不存家属个人信息）。

## 9. 对本审核建议的复核及 v0.9 响应

### 9.1 哪些判断有价值

原审核抓到了患者任务层的真实空白：腹水/腹胀与体重营养误读、术后肠功能和造口生活影响、遗传报告后的家庭疑问；并指出手术、分子结果、神经毒性、复发和放疗在文字中有提及，却缺少可走查的页面行为。这些不应被通用“症状记录/治疗记录”掩盖。原报告用文件命中数和五层覆盖矩阵定位了规范缺口，作为规格完整性检查有效。

### 9.2 需要收紧的方法与风险边界

- **原审核不是用户研究或临床审查。** “最常见”“最需要”等排序没有在本项目患者访谈或可追溯流行病学资料中验证；HVT 分值表达审核者判断，不可当作患者偏好、疾病负担率或项目优先级事实。该报告明确承认没有访谈/临床审核，这是重要限制。
- **“B级阻塞”含义容易被过度解读。** 原报告中的B表示相对其扫描框架缺少文档覆盖，不证明该功能必须进入一期开发。现阶段可以要求规格中有场景和边界，但应由患者价值、第一期范围、实现负担、指南适用性共同决定是否进入原型/生产。
- **OV-03 的自动症状组合与“立即急诊”文案不能直接采用。** 这属于急症分诊/处置边界，不是单纯体验提示。现有规格不做症状算法；如提供紧急联系内容，应来自经临床审核的地区化来源/院方计划，离线可见且能明确标注来源，不能声称产品完成分诊。症状记录不能延迟寻求帮助。
- **OV-02 的腹围/穿刺结构不应提前冻结。** 腹围自测位置和可重复性待验证；不应成为录入义务。穿刺材料可保留原文、日期、机构和患者确认的量/单位，结构化字段保持候选，不让单个患者记录被当作医疗操作指令。
- **OV-09 的造口护理超出通用工作台可安全生成的内容。** 一期可记录患者自述、日常影响和已获得的院方指导并准备问题；换袋、皮肤处理、饮食/气味建议须引用适用于患者的专业资料，不能由产品自行编写。排便/失禁字段自愿、低负担，不进行未经验证的严重度评分。
- **OV-10 的患者/家属利益真实，但家系场景需要隐私设计。** 原报告提出记录“已告知/未告知/暂不想”并承诺不存家属个人信息，依然会无必要地把家庭沟通状态固化为敏感患者数据。v0.9 将是否讨论设为患者主动选择，不收集家属身份、告知状态或概率；不替代遗传咨询。
- **指标场景 OV-04 不宜因五层齐全而视为问题已解决。** 文档矩阵完整不代表一图秀交互、患者可理解性和使用负担已经通过原型确认。本项目已有专门的动态多指标/治疗轨验收，但仍需浏览器实测和患者走查。

### 9.3 当前设计文档的响应

SPEC v0.9 已增加 OVC8 腹部症状/腹水与穿刺、OVC9 术后排便/造口生活影响、OVC10 遗传报告后的自选咨询准备；CORE-MODULES、SCHEMA、UI-DESIGN 和 ACCEPTANCE 增加相应模块行为、扩展候选与 AC33–AC36。手术、靶向/维持、复发、放疗仍以原有 OVC1–OVC7 表述为准，补充 UI 规则要求。v3 HTML 现加入 OVC8–OVC10 任务入口和内存模拟交互，并把身体变化摘要连到一图秀、遗传问题连到复诊问题；当前**文档覆盖缺口已回应，原型有了可走查交互**。原报告的“B=4/G1不通过”数值是 v0.7 快照结果，不能直接描述 v0.9。

本次完成规格与静态原型响应，使用 Playwright 对本机HTML作了页面入口和渲染走查；完整浏览器行为验收仍待逐项完成，患者/照护者可用性和 AC33–AC36 均未验证。临床急症说明、腹围测量方法、造口护理内容及遗传咨询表述仍列为发布前专业审核项；没有审核前不进入指令性提示，更不进入生产建议。

### 9.4 G1 判定更新

- **文档完整性：** 原始四项B类差异均有场景、边界、数据候选和验收编号的设计响应，可从文档追踪。
- **原型覆盖：** 三个场景均有入口；腹部/排便记录可保存并在一图秀回顾，遗传问题可加入复诊问题。尚未对所有状态、窄屏、可访问性和导出逐项验收。
- **患者/照护者可用性：** 未验证。仍需目标用户走查，重点检查它们是否确实帮助当前任务、是否增加病人负担。
- **临床/指南安全性：** 未验证。急症、护理和遗传内容均须来源及专业审查。
- **结论：** v0.9 解决的是文档层缺项，不等同G1签字或生产开发放行。
